# Storage image derivatives

The storage API supports three generated image representations: JPEG at original display dimensions selected by `Object-Image-Quality`, reduced still images, and video thumbnails with optional reduction. Quality values 1–100 map to FFmpeg MJPEG quantizers with `round(2 + 29 × (100 − quality) / 99)`. The reduced-image encoder retains its existing quality search. Generated images never change the source object.

The additive `get_image_derivative` store method accepts a derivative request and cache admission policy. Its default implementation generates with existing store methods so custom stores remain compatible. The filesystem store resolves one immutable object file and its indexed payload digest before cache lookup. It checks source length, path, and content type before serving a hit. Generation uses that same file snapshot. The payload digest comes from the existing version 1 object metadata; the on-disk object format does not change.

The filesystem cache identity hashes the payload digest, source media type, transformation kind and settings, and an implementation version. It omits logical key, object UUID, and admission policy. Identical payloads share entries across keys. A replacement with different content gets a different identity. The cache stores a versioned header, identity, content type, length, and payload in each file beneath `derivative-cache/cache/`. Temporary entries are written beneath `derivative-cache/parts/` and published by hard link so the first concurrent publisher wins. Startup removes abandoned parts and scans occupancy. The cache has no in-memory entry index.

The cache admits results only when capacity permits. Hits update their modification time no more often than the configured interval. Periodic eviction removes the oldest files toward the configured occupancy target; startup enforces capacity. Cache read and write failures are logged and image generation continues where possible. The cache task stops when the filesystem store is dropped. The old `thumbnail-cache/` files are removed only when they match known legacy cache names, after the new cache initializes. Unknown files and original objects are preserved. Cached derivatives can be discarded and regenerated; there is no database migration.

`Object-Image-Cache: true` reads and admits missing results; `false` reads but does not admit. Omitted flags default to `false` on quality and reduced images and `true` on thumbnails. Reduced thumbnails may cache both the extracted JPEG and final reduced output. The storage application exposes capacity, per-entry limit, eviction interval, eviction target, and access timestamp interval in `[derivative_cache]`.
